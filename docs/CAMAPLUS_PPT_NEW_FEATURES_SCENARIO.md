# CAMA Plus 신규 기능 PPT 시나리오

> 목적: Cafe24(camaplus)에 추가된 **신규 기능**을 중심으로 발표용 PPT를 만들기 위한 시나리오·슬라이드 구성안  
> 대상: 내부 공유 / 데모 / 이해관계자 설명  
> 권장 발표 시간: **15~20분** (데모 포함 시 25분)  
> 작성 기준: 환자 앱(WebView SPA) · 환자 APK · 의사 태블릿 · 환자 관리(의사/관리자) 웹

---

## 0. 발표 한 줄 메시지

**환자가 스스로 가입·로그인하고, 걸음·심박 등 생체 정보를 모으며, 말로도 의사를 묻고, 그 자료가 진료 현장의 의사 태블릿에 바로 보이도록 연결했다.**

---

## 1. PPT 전체 구성 (권장 목차)

| # | 섹션 | 슬라이드 수(권장) | 발표 비중 |
|---|------|------------------|----------|

## 2. 데모 스토리라인 (한 명의 환자·한 번의 진료)

발표 중 시연이 있다면 아래 **한 줄기 스토리**로 이어가면 흐름이 끊기지 않습니다.

```text
[환자] 가입/로그인
   → 아이디·비밀번호 찾기 확인
   → 내 상세정보에서 이메일·비밀번호 변경
   → 앱 사용 중 걸음수가 자동 저장됨
   → 마이페이지에서 「진찰시 문의사항」작성 (말로 입력)
   → 「의사앱 자료전송」: 태블릿 QR 스캔 → BLE 전송
[의사 태블릿] 건강 데이터 탭 + 문의사항 탭에서 확인
[관리자/의사 웹] 환자 모니터링·서비스 신청·APK 관리 등 운영 기능
```

# A. 오프닝

### 슬라이드 A-1. 표지

- **제목:** CAMA Plus 신규 기능 소개
- **부제:** 로그인 · 생체정보 · 의사 문의 · 태블릿 연동 · 환자 관리
- **환경:** camaplus.cafe24.com / CAMA Plus 환자 앱 / 의사 태블릿

### 슬라이드 A-2. 오늘 다룰 다섯 가지

1. **로그인·계정** — 가입부터 찾기·초기화·내정보·비밀번호 변경까지
2. **생체 정보 수집** — 걸음수 자동 동기화, 심박 등 바이탈 구조
3. **의사 문의 작성** — 텍스트 + **말로 입력(음성→글자)**
4. **의사 태블릿 연동** — QR·BLE로 자료 전달, 태블릿에서 조회
5. **환자 관리앱** — 관리자/의사 웹에 추가된 운영 기능

### 슬라이드 A-3. Before → After (한 장 요약)

| 영역 | 이전 | 신규 |
|------|------|------|
| 계정 | 제한적 / 찾기·수정 UX 부족 | ID·PW 찾기·초기화, 이메일, 내정보·비번 변경 |
| 생체정보 | 코칭 등 일부 상황에서만 걸음 저장 | 로그인·앱 사용 시 **자동 동기화** |
| 의사 문의 | 메뉴·작성 흐름 미비 | **진찰시 문의사항** + 음성 입력 |
| 진료 현장 | 서버만 보거나 연동 약함 | **환자 폰 → 의사 태블릿** 직접 전달 |
| 운영 | 모니터링·APK 등 분산 | 관리자/의사 웹 **환자 관리 기능 정비** |

**발표 멘트 예:**  
「오늘은 기능 목록이 아니라, **환자가 진료 전까지 어떤 경로로 정보를 만들고 의사에게 넘기는지**를 따라가 보겠습니다.」

# B. ① 로그인·계정 관련 신규 기능

### 슬라이드 B-1. 섹션 표지 — 로그인·계정

- 키워드: **가입 · 로그인 · 찾기 · 초기화 · 내정보 · 비밀번호 변경 · 이메일 안내**

### 슬라이드 B-2. 계정 여정 한눈에 (플로우)

```text
[랜딩] → [회원가입] 또는 [로그인]
              ↓
     [아이디 찾기] / [비밀번호 초기화·찾기]
              ↓
     [홈 / 병원 선택]
              ↓
     [마이페이지 → 내 상세정보]
         · 프로필 수정 (이름/전화/이메일/성별/생년월일)
         · 비밀번호 변경 (현재 비밀번호 확인)
```

### 슬라이드 B-3. 신규·강화된 로그인 관련 기능 목록

| 기능 | 사용자 화면 | 핵심 내용 |
|------|-------------|-----------|
| 회원가입 | 회원가입 | 아이디·전화·(선택)이메일·생년월일 등. 중복 확인 |
| ID/PW 로그인 | 로그인 | 아이디·비밀번호로 로그인, 이후 서비스 진입 |
| 아이디 찾기 | 계정 찾기 | 이름 + 전화번호로 아이디 확인 |
| 비밀번호 초기화 | 계정 찾기 | 아이디 + 이름 + 전화 → **임시 비밀번호 발급** (화면에 안내) |
| 이메일 임시비번 | (이메일 등록 시) | 등록 이메일이 있으면 **메일로도 임시 비밀번호 발송** |
| 내 상세정보 | 마이페이지 | 이름·전화·**이메일**·성별·생년월일 조회 |
| 프로필 수정 | 상세정보 → 수정 | 위 항목 수정 후 저장, 목록에 즉시 반영 |
| 비밀번호 변경 | 상세정보 → 수정 | 현재 비번 → 새 비번 → 확인. 일반 웹과 동일 UX |
| 변경 안내 메일 | (이메일 등록 시) | 비밀번호 변경 성공 시 **안내 메일** 발송 |

### 슬라이드 B-4. 데모 시나리오 — 로그인·계정 (발표용 스크립트)

1. **가입 또는 기존 계정(예: happycog)으로 로그인**한다.  
2. 로그아웃 후 **아이디 찾기**로 이름·전화를 입력해 아이디가 나오는지 보여준다.  
3. **비밀번호 초기화** 후 임시 비밀번호로 로그인한다. (이메일 등록 계정이면 “메일도 발송됨” 문구 강조)  
4. 마이페이지 → **내 상세정보**에서 이메일이 보이는지 확인한다.  
5. **수정** → 이름/전화/이메일 변경 → 저장 → 목록이 바로 바뀌는 것을 보여준다.  
6. 같은 화면에서 **비밀번호 변경** → 현재/새/확인 입력 → 성공 메시지 + (이메일 있으면) 안내 메일 언급.

**강조 멘트:**  
「비밀번호를 ‘잃어버렸을 때’와 ‘알고 있을 때 바꾸는 것’을 분리했습니다. 찾기·초기화는 본인 확인, 변경은 현재 비밀번호 확인입니다.」

### 슬라이드 B-5. 이메일 역할 정리 (한 장)

| 상황 | 메일 역할 |
|------|-----------|
| 비밀번호 초기화 | 임시 비밀번호 전달 (있을 때) |
| 비밀번호 변경 | **변경되었다는 보안 안내** (새 비번은 메일에 넣지 않음) |
| 미등록 | 기능은 동작, 메일만 생략 |

# C. ② 생체 정보 수집 (발걸음 · 심박수 등)

### 슬라이드 C-1. 섹션 표지 — 생체 정보

- 키워드: **걸음수 자동 동기화 · 심박/바이탈 · 서버 저장 · 진료 자료로 연결**

### 슬라이드 C-2. 왜 필요한가

- 의사가 태블릿에서 환자 상태를 보려면, **환자 폰의 데이터가 먼저 쌓여 있어야** 한다.  
- 예전에는 코칭 등 **특정 화면에서만** 걸음을 저장하는 경우가 많았다.  
- 신규: 앱을 **켜고 쓰는 동안 자동으로** 오늘 걸음수를 서버에 맞춘다.

### 슬라이드 C-3. 걸음수 — 신규 동작

| 시점 | 동작 |
|------|------|
| 로그인 후 | 오늘 걸음수를 기기에서 읽어 서버에 저장 |
| 앱을 다시 켤 때(포그라운드) | 일정 간격으로 재동기화 |
| 의사앱 자료전송 직전 | 최신 걸음으로 한 번 더 맞춘 뒤 전송 |
| 마이페이지 | **걸음수** 메뉴에서 이력 확인 |
| 코칭 | 신체활동 확인 팝업에서도 기기 걸음 반영 |

**데이터 흐름 (발표용 단순화):**

```text
환자 폰(센서/헬스) → CAMA Plus 앱 → 서버(일별 걸음 이력) → (필요 시) 의사 태블릿 전송
```

### 슬라이드 C-4. 심박·바이탈 등

| 항목 | 내용 |
|------|------|
| 지원 개념 | 심박수, 혈압, 산소포화도, 체온, 호흡 등 바이탈 유형 |
| 서버 | 바이탈 이력 API · (배치) 심박 통계 등 |
| 앱 | Health Connect 등 네이티브 읽기 기반 확장 |
| 현재 데모 포인트 | **걸음 자동 sync는 실제 사용 가능**, 심박은 API·구조·태블릿 차트까지 연계되는 **건강 데이터 축**으로 설명 |

**발표 멘트 예:**  
「오늘은 ‘걸음이 매일 쌓인다’는 점을 중심으로 보여드리고, 심박은 같은 건강 데이터 파이프라인으로 확장되는 영역입니다.」

### 슬라이드 C-5. 데모 시나리오 — 생체정보

1. 환자 앱 로그인 상태 확인.  
2. (가능하면) 걸음 권한 허용 후 앱 재진입 → 서버/마이페이지 걸음 반영.  
3. 마이페이지 → **걸음수**에서 오늘·이력을 보여준다.  
4. 「이 데이터가 나중에 의사 태블릿 ‘건강 데이터’ 탭으로 간다」고 미리 연결.

# D. ③ 의사 문의 작성 (텍스트 + 말로 입력)

### 슬라이드 D-1. 섹션 표지 — 진찰시 문의사항

- 키워드: **마이페이지 · 문의 작성 · 음성→글자 · 진료 전 준비**

### 슬라이드 D-2. 기능 개요

- 위치: 마이페이지 → **진찰시 문의사항**
- 환자사 진료 전에 **의사에게 전할 질문·증상을 미리 적어 둔다.**
- 작성·수정·삭제·이력 관리
- 미전송 문의 개수 제한(운영 정책: 미전송 최대 5건 등) 언급 가능

### 슬라이드 D-3. 입력 방식 — 텍스트 + 음성

| 방식 | 설명 |
|------|------|
| 키보드 입력 | 제목·본문을 직접 타이핑 (기본) |
| **말로 입력** | 마이크 버튼 → 음성 인식(한국어) → **같은 본문란에 글자로 붙임** |

**중요 메시지 (PPT에 큰 글씨로):**  
「음성 파일을 따로 저장하는 것이 아니라, **말로 말한 내용이 문의 텍스트가 됩니다.**」

- 앱(WebView)에서 동작 (네이티브 음성 인식 브릿지)
- 브라우저 단독에서는 마이크 UI가 제한될 수 있음 → 데모는 **환자 APK** 권장

### 슬라이드 D-4. 데모 시나리오 — 문의 작성

1. 마이페이지 → **진찰시 문의사항** 진입.  
2. 새 문의 작성: 제목 입력.  
3. 본문에서 **마이크**로 「요즘 아침에 숨이 차고 걸을 때 숨이 차요」 등 말하기 → 글자 반영.  
4. 키보드로 한두 줄 보완 후 저장.  
5. 목록에 남은 것을 확인하고, 「아직 의사에게 보낸 상태는 아니다. 다음 단계에서 태블릿으로 넘긴다」고 연결.

# E. ④ 의사 앱(태블릿) 연동 · 문의·건강자료 조회

### 슬라이드 E-1. 섹션 표지 — 의사 태블릿 연동

- 키워드: **QR · BLE · 오프라인 전달 · 건강 데이터 · 문의사항**

### 슬라이드 E-2. 현장 시나리오 (한 장 스토리)

```text
[의사 태블릿] QR 대기 화면 표시 (BLE 수신 준비)
        ↑ 스캔
[환자 폰] 마이페이지 → 의사앱 자료전송
        → 보낼 자료 확인 (걸음·문의 등)
        → 태블릿으로 전송
        ↓
[의사 태블릿 대시보드]
   · 건강 데이터 탭 (걸음 등)
   · 문의사항 탭 (환자가 미리 적은 질문)
```

**한 줄:** 클라우드만 보는 것이 아니라, **진료실에서 환자 폰 → 의사 태블릿으로 바로 넘긴다.**

### 슬라이드 E-3. 환자 앱 / 의사 태블릿 역할

| 쪽 | 화면·동작 |
|----|-----------|
| 환자 | **의사앱 자료전송** — QR 스캔 → 미리보기 → 전송 |
| 환자 | 전송 전 걸음 최신화, 문의·건강 페이로드 구성 |
| 태블릿 | QR 대기 → 수신 → **대시보드** |
| 태블릿 | **건강 데이터** 탭 / **문의사항** 탭 |

### 슬라이드 E-4. 데모 시나리오 — 연동 (발표 하이라이트)

1. 의사 태블릿에서 QR 대기 화면을 띄운다.  
2. 환자 앱 → **의사앱 자료전송** → QR 스캔.  
3. 전송 내용(환자명, 걸음, 문의 목록)을 미리 보여준 뒤 전송.  
4. 태블릿 **건강 데이터**에서 걸음(차트/수치) 확인.  
5. 태블릿 **문의사항**에서 방금 작성한 문의 제목·본문 확인 (상세 모달까지).  
6. 「의사가 진료 시작 전에 환자 질문과 활동량을 한 화면에서 본다」로 마무리.

### 슬라이드 E-5. 전달되는 자료 (요약 표)

| 자료 | 출처 | 태블릿에서 |
|------|------|------------|
| 환자 이름·식별 | 계정 정보 | 대시보드 헤더 |

| 인증·연동 안정화 | 의사 화면이 서버 API를 안정적으로 호출하도록 정비 |

### 슬라이드 F-4. “누가 무엇을 보나” 역할 정리

| 역할 | 보는 것 |
|------|---------|
| 환자 | 본인 계정, 걸음, 문의 작성, 자료 전송 |
| 의사(태블릿) | **진료 직전** 건강·문의 (현장) |
| 의사(웹) | 병원 환자·서비스 신청 등 **온라인 관리** |
| 관리자 | 전체 모니터링, APK, 지표, 운영 |

**발표 멘트:**  
「문의 내용은 진료 순간의 태블릿에서 보고, 병원 운영·배포는 관리자·의사 웹에서 봅니다.」

### 슬라이드 F-5. 데모 시나리오 — 관리앱 (선택, 짧게)

1. 관리자 로그인 → **환자 모니터링** 목록 1~2명 보여주기.  
2. (시간 되면) **APK 관리**에 버전이 올라와 있는 것 스냅샷.  
3. 의사 웹 → **환자 관리** 또는 **서비스 신청** 화면 한 컷.  
4. 「환자 앱 신규 기능이 쌓여도, 운영 화면이 같이 있어야 배포·관리가 된다」로 마무리.
